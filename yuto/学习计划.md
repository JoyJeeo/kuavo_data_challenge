# Kuavo Data Challenge 深度学习计划

## 1. 学习目标

本计划的目标不是“读完仓库里的文件”，而是建立一套可以验证、可以迁移、可以用于排查问题的系统认知。

完成全部学习后，应具备以下能力：

1. 能独立画出数据转换、策略训练、仿真部署和真机部署的完整架构图。
2. 能准确说明 Kuavo 单臂、双臂、不同末端执行器和移动任务的状态与动作数据契约。
3. 能从一条 ROS 消息开始，追踪它如何进入 LeRobot 数据集和模型输入。
4. 能从一个 LeRobot sample 开始，追踪它如何变成训练 batch、loss 和 checkpoint。
5. 能从一份在线 observation 开始，追踪它如何变成 policy action 和机器人控制命令。
6. 能解释 ACT、Diffusion、PI0、PI0.5 和 GR00T 的核心结构、输入输出与适用边界。
7. 能判断问题属于数据、时间对齐、归一化、模型、处理器、ROS、机器人控制还是评测协议。
8. 能识别当前代码、配置和文档之间的不一致，并以当前实现为准进行判断。

最终验收标准是：给出一份 rosbag、一个训练 checkpoint 或一条在线 ROS 观测，能够完整解释它在系统中的生命周期，并为异常提供有证据的定位路径。

## 2. 学习原则

### 2.1 先建立契约，再阅读实现

阅读任何模块前，先回答四个问题：

1. 输入是什么？
2. 输出是什么？
3. 中间必须保持哪些不变量？
4. 哪些情况下会失败或产生静默错误？

重点不变量包括：

- 特征键名
- Tensor shape
- dtype
- 单位
- 数值范围
- 时间频率
- 左右臂排列顺序
- 训练和部署的一致性

### 2.2 沿数据流阅读，不按目录机械阅读

主阅读顺序为：

```text
数据配置
→ ROS 消息定义与处理
→ 时间对齐
→ LeRobot 数据集
→ 训练框架
→ 具体策略
→ 部署配置
→ 在线观测
→ 动作执行
→ 仿真/真机评测
```

### 2.3 每阶段必须产生可检查的学习成果

只阅读不算完成。每个阶段至少输出一种成果：

- 架构图
- 数据契约表
- Tensor shape 表
- 调用链
- 时序图
- 源码讲解
- 故障分析
- 阶段测验答案

### 2.4 区分三种事实

学习过程中始终区分：

- 当前代码已经实现的能力
- 配置中存在但尚未完整接通的能力
- 文档中规划或描述、但代码尚未实现的能力

## 3. 仓库的核心业务模型

仓库的核心链路是：

```text
Kuavo 仿真器 / 真机 ROS
        ↓
ROS bag 数据转换与帧对齐
        ↓
LeRobot Dataset
        ↓
模仿学习策略训练
        ↓
Policy + Preprocessor + Postprocessor
        ↓
仿真批量评测 / 真机闭环控制
```

仓库主要分为三层：

| 层 | 目录 | 核心职责 |
|---|---|---|
| 数据层 | `kuavo_data/` | rosbag 解析、时间对齐、状态动作拼装、LeRobot 数据生成 |
| 训练层 | `kuavo_train/` | 特征解析、处理器构建、策略封装、训练和 checkpoint |
| 部署层 | `kuavo_deploy/` | ROS 观测、策略推理、动作执行、仿真与真机评测 |

外部依赖边界：

| 外部系统 | 提供的能力 |
|---|---|
| ROS Noetic | Topic、Service、Message、rosbag |
| Kuavo SDK / kuavo-ros-opensource | 机器人状态、机械臂/WBC/底盘控制 |
| LeRobot | 数据集、Processor、Policy 基础实现和训练基础设施 |
| 比赛仿真器 | 场景、reset/start/success 协议和任务成功判定 |
| PyTorch / Transformers / Diffusers | 模型训练、VLM、扩散调度器 |

## 17. 当前仓库的重点实现边界

学习过程中需要持续核对以下事项：

1. LeRobot Python 包版本当前为 `0.4.2`，不要和数据格式版本混淆。
2. `delta_action` 和 `relative_start` 出现在配置中，但未完整进入主数据转换链路。
3. EEF 位姿控制和增量控制仍处于开发状态，稳定路径是关节角控制。
4. 强脑灵巧手转换配置可表达多个自由度，但部署当前只接受一个自由度。
5. 离线 Depth 和在线 Depth 的通道数与归一化路径需要专门核对。
6. 文档中描述了 `checkpoint_run_dir`，当前配置 dataclass 和评测实现没有对应字段。
7. 文档描述了 PI0/PI0.5 部署时自动删除 Depth、注入空 task 和覆盖 tokenizer，当前实现需要逐项核实。
8. GR00T 已进入训练和部署代码，部分文档仍将其描述为预留。
9. SmolVLA 位于 LeRobot 上游，但没有接入 Kuavo 自有训练和部署工厂。
10. `kuavo_service/server.py` 仍依赖旧配置路径，不能直接视为成熟入口。
11. 仓库自有代码缺少系统性的单元测试，文件名中的 test 多为运行/评测脚本。
